sequenceDiagram
    participant C as Credit App / Frontend
    participant G as AegisLLM Gateway
    participant M as Model Router / Registry
    participant K as Kafka
    participant R as Risk Engine
    participant F as Fraud Service
    participant A as Approval / Decisioning
    participant DB as PostgreSQL
    participant Obs as Prometheus / Grafana / Jaeger

    C->>G: Submit loan application
    G->>DB: Store application metadata
    G->>M: Route to credit-risk model
    M->>M: Load approved model version
    M-->>G: Risk / scoring result
    G->>K: Publish credit.application.received
    G->>K: Publish credit.risk.scored
    K->>R: Consume credit.application.received
    R->>DB: Save credit score and risk factors
    R->>K: Publish credit.risk.scored
    K->>F: Consume credit.risk.scored
    F->>DB: Save fraud signal / anomaly checks
    F->>K: Publish fraud.review.required or fraud.clean
    K->>A: Consume final risk signals
    A->>DB: Save approval / rejection decision
    A->>K: Publish credit.decision.final
    G-->>C: Return risk summary / recommendation
    G->>Obs: Emit metrics + traces
    DB->>Obs: Audit events and model registry history
